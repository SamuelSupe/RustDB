# RustDB v1.0.0-beta.1

RustDB `v1.0.0-beta.1` is the first compatibility-bearing Beta of the
single-node OLAP engine. It keeps direct CSV/Parquet access, local Native
storage, the embedded Rust API, and the local CLI, while closing the main
reliability, operations, security, and distribution gaps from the alpha line.

RustDB `v1.0.0-beta.1` 是首个承担兼容性承诺的单机 OLAP Beta。它保留 CSV/Parquet
直读、本地 Native 存储、嵌入式 Rust API 与本地 CLI，并集中补齐 alpha 阶段在可靠性、
运维、安全和发行方面的关键缺口。

> **Beta notice / Beta 提示**
>
> This release is for evaluation and controlled pre-production use. It has no
> production SLA, availability SLO, or claim of long-running soak coverage.
>
> 本版本面向评估和受控的预生产使用，不提供生产 SLA、可用性 SLO，也不声称已完成
> 长时间 soak 验证。

## Highlights / 主要变化

- **New compatibility epoch / 新兼容 epoch** — Native marker epoch `3` starts
  the Beta contract. Alpha epoch `1`/`2` directories are rejected before any
  mutation and must be rebuilt by importing CSV/Parquet into a fresh Beta
  database.
- **Idempotent Native import / 幂等 Native 导入** — local CLI and
  `Session::import` persist CSV/Parquet with a caller-supplied import ID. A
  durable receipt makes exact retries replay-safe, while changed requests fail
  with an explicit conflict. This is the primary alpha-to-Beta rebuild path.
- **Native integrity operations / Native 完整性运维** — strictly read-only
  `native check`, conservative plan-first `native repair`, stable error codes,
  filesystem reserve admission, and redacted versioned diagnostics.
- **Multi-principal HTTP security / 多 principal HTTP 安全** — Query and Admin
  roles, digest-only credential storage, overlapping token rotation, per-query
  ownership, TLS-only serving, and an explicit development-only no-auth mode.
- **Observable service / 可观测服务** — structured JSON logs, Admin-protected
  low-cardinality Prometheus metrics, and private rotating JSONL audit records.
- **Verified HTTP results / HTTP 结果校验** — every persisted result batch has
  a SHA-256 verified on read and restart recovery; corruption fails and
  invalidates the retained result instead of returning altered rows.
- **Transaction abandonment convergence / 事务弃置收敛** — dropping a result
  remains non-blocking, the Session retains the transaction until every result
  and query worker stops, and an automatically rolled-back transaction no
  longer poisons the next `BEGIN`.
- **Versioned operations / 版本化运维** — strict `schema_version = 1` TOML,
  deterministic CLI/environment/file precedence, configuration validation,
  and a bilingual operator handbook.
- **Release supply chain / 发行供应链** — pinned build/runtime images and
  release/security GitHub Actions, Linux x86_64/AArch64 non-root OCI images, source SBOM,
  dependency/secret/container scanning, SHA-256 files, keyless signatures,
  provenance attestations, and commit-bound acceptance trailers.
- **Patched object storage stack / 已修复的对象存储栈** — object-store `0.14.1`
  and quick-xml `0.41.0` remove the two XML parsing advisories that blocked the
  release gate, while Arrow/Parquet remains pinned to `59.1.0` and the live
  MinIO range, multipart, and conditional-read paths remain covered.

## Compatibility / 兼容性

Compatibility begins with beta.1; alpha artifacts do not inherit it. During
the Beta series RustDB supports the current and previous two Beta revisions of
the Native format and documented public surfaces. Stable surfaces include the
outer Rust API, CLI, `/v1`, versioned service configuration, error codes, and
retry classes. Internal plans, operators, and physical storage details remain
private.

兼容承诺从 beta.1 开始，alpha 产物不追溯适用。Beta 系列支持当前及前两个 Beta
revision 的 Native 格式和已记录公开接口。稳定面包括外层 Rust API、CLI、`/v1`、
版本化服务配置、错误码和 retry class；内部 plan、operator 和物理存储细节不公开。

There is intentionally no in-place alpha migration. Follow the
[Beta migration guide](../migration-v1-beta.md), preserve the alpha directory,
re-import into a new Beta directory, verify row counts and query checksums, and
create a new backup before switching readers.

本版本刻意不提供 alpha 原地迁移。请按 [Beta 迁移指南](../migration-v1-beta.md)保留
alpha 目录，将源 CSV/Parquet 重新导入新的 Beta 目录，校验行数与查询 checksum，并在
切流前创建新备份。

## Supported deployment / 支持的部署

| Target | Status |
| --- | --- |
| Linux x86_64 | Supported binary and OCI image |
| Linux AArch64 | Supported binary and OCI image |
| macOS Apple Silicon | Supported binary for CLI, embedded use, and development |
| AWS S3 | Supported default-credential path |
| MinIO `RELEASE.2025-04-22T22-12-26Z` | Tested S3-compatible target |
| Other S3-compatible services | Best effort, deployment validation required |
| Windows, macOS Intel | Unsupported |

The OCI image runs as UID/GID `10001:10001` and uses a digest-pinned Debian
Bookworm Slim runtime. Keep Native data on a local filesystem with atomic
rename, `fsync`, and advisory locks. See the [operator guide](../operator-guide.md)
or [中文运维指南](../operator-guide.zh-CN.md).

OCI 镜像以 UID/GID `10001:10001` 运行，runtime 为 digest 锁定的 Debian
Bookworm Slim。Native 数据必须位于支持原子 rename、`fsync` 和 advisory lock 的
本地文件系统。完整要求见上述中英文运维指南。

## Packages and verification / 安装包与验证

The GitHub prerelease contains:

- Linux x86_64, Linux AArch64, and macOS Apple Silicon archives;
- one SHA-256 file and one Sigstore bundle per archive;
- the OpenAPI v1 document, checksum, and Sigstore bundle;
- a source SPDX JSON SBOM, checksum, and Sigstore bundle;
- GitHub build-provenance attestations for the three archives;
- a signed multi-platform GHCR image with BuildKit provenance and SBOM.

GitHub prerelease 包含三平台归档、逐文件 SHA-256 与 Sigstore bundle、OpenAPI v1、
SPDX JSON source SBOM、三份归档的 GitHub provenance attestation，以及带 BuildKit
provenance/SBOM 的已签名多平台 GHCR 镜像。

Verify an archive before installation:

```sh
sha256sum -c rustdb-v1.0.0-beta.1-linux-x86_64.tar.gz.sha256
cosign verify-blob \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp \
  '^https://github.com/SamuelSupe/RustDB/.github/workflows/dist.yml@refs/tags/v1.0.0-beta.1$' \
  --bundle rustdb-v1.0.0-beta.1-linux-x86_64.tar.gz.sigstore.json \
  rustdb-v1.0.0-beta.1-linux-x86_64.tar.gz
gh attestation verify rustdb-v1.0.0-beta.1-linux-x86_64.tar.gz \
  --repo SamuelSupe/RustDB
```

Pin the OCI image by digest in deployment manifests and verify the same GitHub
Actions identity with `cosign verify`.

部署前必须执行 SHA-256、Sigstore 和 provenance 验证；生产式清单应按 digest 固定 OCI
镜像，并以 `cosign verify` 验证相同 GitHub Actions identity。

## Release gate / 发行门禁

Publication requires one focused `scripts/ci/beta_acceptance.sh` run on a
4-core/16-GiB class host. It covers the complete default OrbStack gate, an
explicit equivalent local/MinIO CSV-or-Parquet workload of at least 100 GiB and
10,000 files/objects under 2-GiB and 4-GiB limits with eight clients, and one
preloaded ClickBench pass. ClickBench uses four CPUs, a 12-GiB container limit,
a 4-GiB engine budget, batch 8192, and I/O concurrency 16. Canonical official
queries remain pinned as the source/full profile; the functional gate executes
a versioned derivative with complete tie-breakers and binds both identities.
The immutable output directory retains normalized fixture inventories, logs,
reports, and commit-bound `evidence.json`. It records a functional baseline,
not a performance comparison or performance SLA. A digest-pinned
`clickhouse-local` rowset is used only to generate and review the correctness
oracle, never as a release-time performance peer.

发布前在 4 核 16 GiB 级主机只执行一次 `scripts/ci/beta_acceptance.sh`：完整默认
OrbStack 门禁、等价且显式提供的本地/MinIO CSV 或 Parquet 样本（至少 100 GiB、
10,000 文件/对象）、2 GiB/4 GiB、8 客户端并发，以及一次预加载 ClickBench。不可复用
的 ClickBench 配置固定为 4 CPU、12 GiB 容器上限、4 GiB Engine 上限、batch 8192 和
I/O 并发 16。官方规范查询仍作为来源/full profile 固定，功能门禁执行带完整
tie-breaker 的版本化派生查询，并同时绑定两份身份。输出目录保留规范化样本清单、日志、
报告和绑定 commit 的 `evidence.json`。它只记录功能 baseline，不构成性能比较或性能
SLA。按 digest 固定的 `clickhouse-local` 行集只用于生成和复核正确性 oracle，不作为
发行时性能对手。

The release workflow accepts only an annotated tag whose message contains the
accepted commit and `RustDB-Acceptance-Status: passed`. Therefore a published
GitHub release is bound to the explicitly accepted commit. The trailers are an
operator assertion; release artifacts remain a Beta, not a production warranty.

发行 workflow 只接受 tag message 同时包含已验收 commit 和
`RustDB-Acceptance-Status: passed` 的 annotated tag，从而把 GitHub Release 绑定到
明确验收的 commit。该 trailer 是运维断言，不是生产质保。

## Known Beta limits / 已知 Beta 边界

- HTTP remains read-only; writes, maintenance, principal changes, and source
  administration are local-only operations while the server is stopped.
- RustDB is single-node and provides no HA, replication, distributed execution,
  remote DML, PostgreSQL/Flight protocol, browser UI, or generated SDK.
- RustDB does not encrypt Native data, results, audit logs, or credentials at
  rest; use encrypted host volumes and an external secret-management process.
- A process-memory limit is not a hard RSS limit. Decoder and allocator
  transients may briefly exceed accounted engine reservations.
- Native backup excludes HTTP security state, audit records, and retained query
  results. Back up required state separately and test restore procedures.
- Other S3-compatible services are not assumed compatible solely because they
  implement an S3-shaped API.
- The acceptance run is intentionally not a long soak, chaos campaign, or
  repeated low-memory Spill benchmark.

- HTTP 保持只读；写入、维护、principal 修改和数据源管理只能在停服后本地执行。
- 仍为单机引擎，不提供 HA、复制、分布式执行、远程 DML、PostgreSQL/Flight 协议、
  浏览器 UI 或生成式 SDK。
- RustDB 不提供 Native、结果、审计或凭证的静态加密，应使用加密宿主机卷和外部
  secret management。
- Engine 内存上限不是严格 RSS 上限，decoder/allocator 瞬时内存可能短暂超过记账值。
- Native backup 不包含 HTTP 安全状态、审计日志或保留结果；需要的状态必须独立备份并
  演练恢复。
- 其他 S3-compatible 服务不能因为 API 外形相似就默认兼容。
- 本次验收刻意不是长时间 soak、chaos campaign 或重复低内存 Spill 基准。

For the precise SQL/type boundary, see [compatibility.md](../compatibility.md).
For operations and incident response, use the bilingual operator guide.

SQL/类型边界以 [compatibility.md](../compatibility.md) 为准；部署和故障处理以中英文
运维指南为准。
