# RustDB v1.0.0-beta.2

RustDB `v1.0.0-beta.2` is a reliability reset for the single-node OLAP engine.
It keeps the Beta 1 SQL and data-format scope while replacing the Native,
service-configuration, and HTTP compatibility boundaries. It remains
pre-production software with no production SLA.

## Breaking fresh-start boundary

- Native databases use format epoch `4`. Epochs `1`, `2`, and `3` are rejected
  before permission changes, locking, WAL recovery, or cleanup.
- Service TOML requires `schema_version = 2`; Beta 1 service state is not
  imported or guessed compatible.
- The read-only HTTP Shell is `/v2`. `/v1` is not served, and the official
  remote client negotiates protocol `v2`.
- There is no in-place migration or rollback contract. Re-import CSV/Parquet
  into a new Native directory and create new HTTP state, principals, tokens,
  certificates, results, and journals.

See [Rebuilding data for Beta 2](https://github.com/SamuelSupe/RustDB/blob/v1.0.0-beta.2/docs/migration-v1-beta.md)
before deployment.

## HTTP reliability contract

- `GET /v2/queries` lists visible Queries newest first with owner isolation,
  state and creation-time filters, bounded pages, and opaque cursors.
- Status always reports `result_available` and, when retained, the result
  expiry, committed row count, bytes, and batch count.
- Shutdown or restart changes unfinished work to terminal `interrupted`.
  Committed Arrow IPC batches remain readable as an explicitly incomplete
  prefix; JSON/NDJSON still require a successfully completed Query.
- Errors retain stable codes, retry classifications, request IDs, optional
  Query IDs, and structured details. The public remote client exposes these
  fields instead of flattening them into message text.

The exact wire contract is [OpenAPI v2](https://github.com/SamuelSupe/RustDB/blob/v1.0.0-beta.2/docs/openapi-v2.yaml).

## Service reliability and operations

- Bounded shutdown stops admission first, drains work to the configured
  deadline, records remaining Queries as `interrupted`, and retains only
  checksum-validated committed Arrow batches.
- Query journal and result formats use new owner markers and epochs. Startup
  rejects incompatible state and recovers interrupted prefixes without
  guessing ownership.
- Blocking result and control-state I/O runs on a fixed, bounded service pool;
  Query TaskGroups converge before managed cleanup.
- A process RSS guard uses the effective host/cgroup limit. The default
  70/80/90% watermarks throttle, reject, then cancel the largest live Query.
- A private Unix Admin socket provides status, token reload/rotation/revocation,
  and bounded shutdown. Near-expiry TLS leaves are renewed and hot-reloaded.
- `rustdb service check|repair` validates principals, Query journals, and
  retained results. Repairs are conservative and marker-gated.
- `rustdb backup`, `backup-check`, and `restore` now operate on one verified
  service bundle containing Native data plus safe HTTP control state. Query
  journal/results, audit, Spill/temp, locks, and sockets remain excluded.
- Each transactional statement has an internal savepoint. A failed, cancelled,
  or abandoned statement rolls back its own staged changes without poisoning
  the surrounding transaction.

## Release acceptance

Publication requires one commit-bound OrbStack acceptance run: routine quality,
TPC-H SF1 local/MinIO correctness, the existing 100 GiB / 10,000-file workload
at 2 GiB and 4 GiB with eight clients, one functional ClickBench pass, and one
bounded 60-minute lifecycle/fault-injection stage. It is not a repeated timing,
low-memory Spill, cross-engine comparison, or production soak. The annotated
tag must bind the accepted commit and passed evidence.

## Deliberate limits

Beta 2 adds no SQL surface, data format, Web UI, remote DML, SDK, distributed
execution, at-rest encryption, or new platform. It remains a single-node,
read-only remote Shell over a locally administered Native database. See the
[compatibility matrix](https://github.com/SamuelSupe/RustDB/blob/v1.0.0-beta.2/docs/compatibility.md)
and the operator guides for the complete boundary.
