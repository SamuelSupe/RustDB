# RustDB v0.9.0-alpha.1

RustDB v0.9 adds a secure, read-only HTTP Shell while preserving the existing
single-node Native OLAP engine and CLI output experience. One `rustdb serve`
process exposes one Native database; `rustdb shell` submits background Queries,
waits, downloads immutable result pages, and renders `table`, `csv`, or
`jsonl`.

RustDB v0.9 在现有单机 Native OLAP 引擎上增加安全的只读 HTTP Shell，并保留
CLI 原有输出体验。一个 `rustdb serve` 进程服务一个 Native 数据库；
`rustdb shell` 提交后台 Query、等待完成、分页下载不可变结果，并输出
`table`、`csv` 或 `jsonl`。

> **Alpha notice / Alpha 提示**
>
> This release is intended for evaluation and controlled deployments. The HTTP
> protocol is versioned, but operational and Native alpha compatibility is not
> yet a production-stability promise.
>
> 本版本用于评估和受控部署。HTTP 协议已进行版本化，但运行与 Native Alpha
> 兼容性尚未承诺生产级稳定。

## Highlights / 主要变化

- **Remote CLI, not a browser UI / 远程 CLI，而非浏览器 UI** — named offline
  profiles, interactive and `-c`/`-f` script modes, `Ctrl-C` cancellation, and
  the existing three local renderers.
- **Small public `/v1` protocol / 小型公开 `/v1` 协议** — OpenAPI 3.1,
  authenticated capability negotiation, background Query status, immutable
  JSON/NDJSON pagination, cancellation, and terminal deletion.
- **Read-only by construction / 结构化只读边界** — only query, metadata, and
  explain statements; checks at both bound-statement and physical-plan
  boundaries; no direct file function or remote source management.
- **Safe retry semantics / 安全重试语义** — required Idempotency Keys return
  the original Query for an identical payload and reject conflicting reuse.
- **Bounded lifecycle / 有界生命周期** — FIFO admission, timeout and
  TaskGroup cancellation, indexed Arrow IPC results, TTL and disk quotas, and
  cleanup after complete consumption.
- **Local persistent sources / 本地持久数据源** — CSV/Parquet definitions are
  administered only on the server host while serving is stopped; credentials
  are never persisted.
- **Secure first start / 安全首次启动** — loopback listener by default,
  mandatory TLS, generated local CA and renewable leaf certificate, one random
  Bearer Token, and offline Profile export/import.

## HTTP contract / HTTP 协议

The public surface is deliberately limited:

```text
GET    /healthz
GET    /readyz
GET    /v1/info
POST   /v1/queries
GET    /v1/queries/{query_id}
GET    /v1/queries/{query_id}/results
POST   /v1/queries/{query_id}/cancel
DELETE /v1/queries/{query_id}
```

Only health and readiness are unauthenticated, and both return minimal state.
Every `/v1` request requires the generated Bearer Token, verified before body
or query-parameter parsing. Results are readable only after successful
completion and can be fetched repeatedly by opaque Cursor or immutable offset.
See the historical [OpenAPI v1 contract](https://github.com/SamuelSupe/RustDB/blob/v0.9.0-alpha.1/docs/openapi-v1.yaml),
[English guide](https://github.com/SamuelSupe/RustDB/blob/v0.9.0-alpha.1/docs/http-shell.md), and
[中文指南](https://github.com/SamuelSupe/RustDB/blob/v0.9.0-alpha.1/docs/http-shell.zh-CN.md).

公开接口刻意保持精简。只有最小化的健康和就绪检查无需认证；所有 `/v1` 请求都
必须携带生成的 Bearer Token，并会在解析 body 或 query parameter 前完成认证。结果仅在
Query 成功完成后可读，可通过不透明 Cursor 或不可变 offset 重复获取。精确契约和使用
方法见上述 OpenAPI 及中英文说明。

## SQL and data boundary / SQL 与数据边界

Remote SQL supports one `SELECT`/`WITH`, `VALUES`, `SHOW`, `DESCRIBE`,
`EXPLAIN`, or `EXPLAIN ANALYZE` statement. It can read Native/system tables and
locally registered CSV/Parquet sources. DDL, DML, transaction or maintenance
commands, direct `read_csv`/`read_parquet`, uploads, and remote source
administration are rejected even when nested.

远程 SQL 每次只允许一条 `SELECT`/`WITH`、`VALUES`、`SHOW`、`DESCRIBE`、
`EXPLAIN` 或 `EXPLAIN ANALYZE`。可读取 Native/系统表及服务端本地注册的
CSV/Parquet；DDL、DML、事务、维护、直接文件函数、上传和远程数据源管理均会被
拒绝，即使它们被隐藏在嵌套查询中。

## Compatibility and migration / 兼容与迁移

The embedded Rust API and local writable CLI remain available. HTTP serving
does not change Native table, WAL, database-marker, or Catalog format versions,
so v0.8 databases do not require a mandatory migration. External source
definitions use an optional atomic Catalog sidecar and are included in Native
backup/restore. Follow [the v0.9 migration guide](../migration-v0.9.md).

嵌入式 Rust API 与本地可写 CLI 保持可用。HTTP 服务不会更改 Native table、
WAL、database marker 或 Catalog 格式版本，因此 v0.8 数据库无需强制迁移。
外部数据源定义使用可选、原子更新的 Catalog 附属文件，并随 Native 备份恢复。
升级步骤见 [v0.9 迁移指南](../migration-v0.9.md)。

## Secure operation / 安全运行

- The listener defaults to `127.0.0.1`; non-loopback binding requires an
  explicit HTTPS advertise URL and matching certificate SAN.
- CORS is disabled and there is no plaintext-HTTP mode.
- Token bytes are read only from a user-private file, never a plaintext CLI
  flag. Rotate offline and redistribute the Profile; the old Token has no grace
  period.
- Server state and temporary results are stored outside the Native database.
  State directories use `0700` and secret/result files use `0600`.
- Logs contain an SQL fingerprint by default, not SQL text or credentials.

- 默认只监听 `127.0.0.1`；非回环监听必须显式提供 HTTPS advertise URL 和匹配
  的证书 SAN。
- CORS 始终关闭，不提供明文 HTTP。
- Token 只从用户私有文件读取，不接受明文命令行参数；离线轮换后旧 Token 无宽限期。
- 服务状态和临时结果位于 Native 数据库之外，目录使用 `0700`，敏感/结果文件使用
  `0600`。
- 日志默认只包含 SQL 指纹，不记录 SQL 原文或凭证。

## Resource defaults / 资源默认值

- one active Query and a 64-entry FIFO queue;
- 30-minute maximum Query time;
- one-hour result TTL;
- global result limit of `min(10 GiB, filesystem capacity * 10%)`;
- per-Query result limit of 25% of the global limit;
- 1,000 rows per page by default, with hard limits of 10,000 rows and 16 MiB.

Deployments may override retention with `--result-directory`,
`--result-ttl-secs`, `--result-global-limit`, and `--result-query-limit`.
Server-local registered sources may receive `--s3-region`, `--s3-endpoint`,
`--s3-path-style`, `--s3-allow-http`, and `--s3-anonymous`; HTTP is an explicit
trusted-development opt-in and anonymous mode is only for public objects.

- 同时执行 1 条 Query，FIFO 最多排队 64 条；
- Query 最长执行 30 分钟；
- 结果 TTL 为 1 小时；
- 总结果配额为 `min(10 GiB, 文件系统容量 * 10%)`；
- 单 Query 结果配额为总配额 25%；
- 默认单页 1,000 行，硬上限为 10,000 行和 16 MiB。

部署可通过 `--result-directory`、`--result-ttl-secs`、`--result-global-limit`、
`--result-query-limit` 覆盖结果保留设置。服务端本地注册源可使用 `--s3-region`、
`--s3-endpoint`、`--s3-path-style`、`--s3-allow-http`、`--s3-anonymous`；HTTP 是
显式的可信开发环境 opt-in，匿名模式只适用于公开对象。

Query metadata and retained results are process-local and disappear after a
server restart. Completed results are Arrow IPC fragments with a sparse row
index; JSON/NDJSON pages are encoded on demand and may negotiate gzip.

Query 元数据和保留结果只存在于当前进程，服务重启后不会恢复。完成结果使用带稀疏
行索引的 Arrow IPC 分片保存，JSON/NDJSON 页面按需编码并可协商 gzip。

## Packages / 安装包

Release archives continue to contain one `rustdb` executable for Linux x86_64,
Linux AArch64, and macOS Apple Silicon, plus English and Simplified Chinese
help, install/uninstall scripts, and SHA-256 checksums. The executable now adds
`serve`, `profile import/export`, `datasource`, and remote `shell` commands.

发行包继续为 Linux x86_64、Linux AArch64 和 macOS Apple Silicon 提供单一
`rustdb` 可执行文件，并包含中英文帮助、安装/卸载脚本和 SHA-256 校验。可执行文件
新增 `serve`、`profile import/export`、`datasource` 和远程 `shell` 命令。

## Validation / 验证

The release gate is one complete OrbStack correctness run covering TLS/Profile
bootstrap, authentication, read-only bypass attempts, typed parameters,
idempotency, Query lifecycle, pagination and encoding, cancellation/timeout,
result quota/TTL, cleanup, and all three CLI output formats. v0.9 does not add a
performance threshold or long soak requirement.

发行门禁为一次完整 OrbStack 正确性测试，覆盖 TLS/Profile 初始化、认证、只读绕过、
类型化参数、幂等、Query 生命周期、分页与编码、取消/超时、结果配额/TTL、清理和
三种 CLI 输出。本版本不增加性能阈值或长时间 soak 要求。

## Known alpha boundaries / 已知 Alpha 边界

- A Query must finish and materialize its Arrow IPC result before any row can
  be fetched, increasing time-to-first-row and disk I/O versus true streaming.
- One shared Token provides no user-level identity or Query ownership. Anyone
  with the Token and an unguessable Query ID can access that Query.
- Query IDs and results do not survive restart.
- Result files are permission-restricted but not encrypted at rest by RustDB.
- Natural JSON numbers may lose Int64/UInt64/Decimal precision in third-party
  floating-point JSON decoders; the official CLI is schema-aware and exact.
- There is no browser UI, CORS, write API, remote Session, multi-user RBAC,
  generated SDK, remote source management, or PostgreSQL/Flight protocol.

- Query 必须先执行完成并物化 Arrow IPC 结果，之后才能读取任何一行；相比真正流式
  协议，首行延迟和磁盘 I/O 更高。
- 单一共享 Token 不提供用户身份或 Query 所有权；持有 Token 和不可猜测 Query ID
  的客户端即可访问该 Query。
- Query ID 和结果不会跨服务重启恢复。
- 结果文件使用严格权限，但 RustDB 不提供静态加密。
- 第三方浮点 JSON 解析器可能丢失 Int64/UInt64/Decimal 精度；官方 CLI 根据 Schema
  精确解析。
- 不提供浏览器 UI、CORS、写入 API、远程 Session、多用户 RBAC、生成式 SDK、
  远程数据源管理或 PostgreSQL/Flight 协议。
