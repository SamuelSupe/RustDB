# RustDB v1.0.0-beta.3

RustDB `v1.0.0-beta.3` is a focused execution and bounded-memory follow-up to
Beta 2. It keeps the single-node OLAP scope and Beta 2 compatibility
boundaries. This remains evaluation and pre-production software with no
production SLA.

## Highlights

- **Bounded window aggregates** — Bounded `COUNT(*)` derives counts directly
  from frame boundaries rather than visiting each row, preserving empty-frame
  and partition semantics across `ROWS`, `RANGE`, and `GROUPS`. For spilled
  partitions, a sparse batch index can seek near the requested row and avoid
  rereading the full prefix; each frame is still aggregated independently.
- **Numeric `MIN`/`MAX` batches** — Existing numeric and decimal `MIN`/`MAX`
  aggregates now use the mixed global batch path while preserving the existing
  null and type behavior.
- **Lower join residual memory** — Residual predicates materialize only the
  columns they reference, and candidate workspace accounting charges the same
  projection. Join output batches are bounded by the query memory budget,
  including low-memory execution.
- **Lower Top-K payload work** — Top-K concatenates sort keys first, then
  interleaves only the selected payload rows from the input batches.
- **EOF admission fix** — A public datasource can reach EOF without waiting for
  a new memory reservation after its input is exhausted, avoiding an admission
  stall when the query is full.

## Spill coverage

Low-memory inner and left hash-join spill scenarios are active in the CI check
set. They cover bounded output batches, row preservation, memory limits, and
spill-directory cleanup.

## Compatibility

Beta 3 continues the Beta 2 boundaries:

- Native format epoch `4`;
- service configuration `schema_version = 2`;
- read-only HTTP Shell `/v2` and remote protocol `v2`.

This release introduces no new migration format and no in-place migration or
rollback contract. Follow the existing [Beta migration guide](../migration-v1-beta.md)
when a fresh Native or service state must be rebuilt.

No new SQL syntax or query surface is announced. The remaining Beta 2 limits
continue to apply: RustDB is a single-node engine with a locally administered
Native database and a read-only remote Shell.

## Verification scope

This maintenance prerelease covers execution and optimizer correctness, service
lifecycle, low-memory joins, lint, and three-platform packaging. The complete
100 GiB/10,000-file local and MinIO acceptance workload and ClickBench are not
part of the completed scope for this release, and no performance multiplier is
reported. The release body will record actual counts at publication without
predeclaring a pass.
