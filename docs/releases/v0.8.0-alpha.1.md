# RustDB v0.8.0-alpha.1

RustDB v0.8 turns the persistent Native store into a transactional, recoverable
single-node OLAP database while retaining direct CSV/Parquet querying over local
files and S3-compatible object stores.

RustDB v0.8 将 Native 持久化存储扩展为支持事务和故障恢复的单机 OLAP 数据库，
同时继续支持直接查询本地及 S3-compatible 对象存储中的 CSV、Parquet 数据。

> **Alpha notice / Alpha 提示**
>
> This release is intended for evaluation and development. Native format and
> public API compatibility are not yet production-stable.
>
> 本版本用于评估与开发；Native 格式及公开 API 尚未承诺生产级稳定性。

## Highlights / 主要变化

- **Transactional Native storage / 事务 Native 存储** — snapshot isolation,
  optimistic multi-writer commits, checksummed WAL recovery, row versions,
  delete vectors, and deterministic durable-outcome reporting.
- **Persistent catalog / 持久 Catalog** — schemas, qualified object names,
  persistent views, transactional table and column DDL, and atomic catalog
  snapshots.
- **Writable SQL / 可写 SQL** — `INSERT VALUES`, `INSERT SELECT`, `UPDATE FROM`,
  `DELETE USING`, `TRUNCATE`, DML `RETURNING`, and explicit transactions through
  SQL and the Rust API.
- **Storage governance / 存储治理** — hard engine and per-table Native disk
  quotas, commit-time aggregate rechecks, `CHECKPOINT`, `COMPACT`, `ANALYZE`,
  `VACUUM`, and system metadata views.
- **COPY and recovery / COPY 与恢复** — local and S3/MinIO CSV/Parquet
  `COPY FROM`/`COPY TO`, verified local and remote Native backup/restore,
  cancellation-safe multipart ownership, and conservative crash-orphan cleanup.
- **Expanded analytical SQL / 扩展分析 SQL** — grouping sets, aggregate filters,
  multi-expression distinct aggregates, bounded window frames, navigation/value
  windows, complete interval handling, `TIME`, timestamp precision,
  `TIMESTAMPTZ`, IANA timezone behavior, and UUID.
- **Operational clarity / 运维可观测性** — structured quota and durable-boundary
  errors, bilingual CLI and installation guides, compatibility documentation,
  and a focused live-MinIO v0.8 acceptance gate.

## Compatibility and migration / 兼容与迁移

Opening a v0.7 Native database remains read-compatible, but v0.8 writes require
an explicit migration because the database marker, catalog, WAL, and table
snapshot formats changed. Follow [the migration guide](../migration-v0.8.md)
before writing to an existing database. The complete supported surface and
deliberate exclusions are documented in the
[compatibility matrix](../compatibility.md).

v0.7 Native 数据库仍可只读打开；由于数据库 marker、Catalog、WAL 与表快照格式
发生变化，使用 v0.8 写入前必须执行显式迁移。请先阅读
[v0.8 迁移指南](../migration-v0.8.md)，完整能力边界见
[兼容矩阵](../compatibility.md)。

## Packages / 安装包

GitHub Release provides validated archives for:

- Linux x86_64;
- Linux AArch64;
- macOS Apple Silicon (AArch64).

Each archive contains the `rustdb` CLI, English and Simplified Chinese help,
installer/uninstaller scripts, and a matching `.sha256` file.

GitHub Release 提供经过校验的 Linux x86_64、Linux AArch64 与 macOS Apple
Silicon 安装包。每个压缩包均包含 `rustdb` CLI、中英文帮助、安装/卸载脚本和
对应的 `.sha256` 文件。

## Validation / 验证

The focused OrbStack `v08` gate completed 257 tests with no failures; the one
long release-soak case remains intentionally opt-in. The gate includes a live
MinIO round trip for CSV/Parquet COPY plus Native backup and restore. Formatting,
strict Clippy, and all-target compilation also passed.

OrbStack `v08` 聚焦门禁共完成 257 项测试且无失败；唯一的长时间 release soak
仍按设计保持手动执行。门禁包含真实 MinIO 上的 CSV/Parquet COPY 与 Native
备份恢复往返，同时已通过格式检查、严格 Clippy 和所有 target 编译。

## Known alpha boundaries / 已知 Alpha 边界

- A process crash after multipart completion but before manifest publication
  can leave an unreferenced completed object. RustDB blocks reuse of that
  non-empty destination until an operator inspects and removes it.
- A single unusually wide COPY batch may conservatively return
  `ResourceExhausted` instead of exceeding the configured memory budget.
- Serializable isolation, savepoints, `MERGE`/upsert, constraints, indexes,
  public time travel, server protocols, replication, and distributed execution
  remain outside v0.8.

- multipart 已完成但 manifest 尚未发布时发生进程崩溃，可能留下未引用对象；
  RustDB 会阻止复用该非空目标，直到运维人员检查并清理。
- 单个异常宽的 COPY batch 可能保守地返回 `ResourceExhausted`，而不会突破
  已配置的内存预算。
- 可串行化隔离、savepoint、`MERGE`/upsert、约束、索引、公开时间旅行、服务协议、
  复制与分布式执行仍不属于 v0.8。
