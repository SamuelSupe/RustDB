# S3 and S3-compatible storage

RustDB accepts `s3://bucket/key` and glob-style `s3://bucket/prefix/*.parquet`
locations. AWS credentials are resolved by `object_store`'s default chain. An
embedded application may instead set `S3Config::credential_provider`; the
provider is held in memory and its credentials are never written to the
Catalog, formatted with `Debug`, or accepted as SQL arguments.

For MinIO and other S3-compatible services, configure an endpoint and usually
path-style addressing:

```sh
export AWS_ACCESS_KEY_ID=local-access-key
export AWS_SECRET_ACCESS_KEY=local-secret-key
export AWS_REGION=us-east-1

docker compose run --rm \
  -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_REGION \
  dev cargo run -- \
  --s3-endpoint http://minio:9000 \
  --s3-path-style --s3-allow-http \
  -c "SELECT count(*) FROM read_parquet('s3://rustdb-tests/events/*.parquet')"
```

Plain HTTP is rejected unless `allow_http`/`--s3-allow-http` is explicitly set.
Endpoint URLs containing user information, query strings, or fragments are
rejected so secrets cannot leak through configuration diagnostics or benchmark
manifests. Anonymous access is mutually exclusive with an explicit credential
provider.

`S3Config::endpoint` takes precedence over `AWS_ENDPOINT_URL_S3`, followed by
`AWS_ENDPOINT_URL` and the legacy `AWS_ENDPOINT`. RustDB applies the same URL
validation to whichever endpoint wins; the remaining `AWS_*` settings continue
to feed the default credential and region configuration.

Before execution RustDB records the size, ETag, and version of every object in
all query scans, then seals that query-wide snapshot. Every Parquet range
request and CSV GET is conditional on the recorded identity. A file may change
between queries, but a change during a query fails that query rather than
combining bytes from different versions. Cancellation interrupts outstanding
list/HEAD/GET work. Metrics include logical S3 resolution, metadata, snapshot,
and data requests plus transferred response bytes.

`Session::execute(...).await` performs SQL binding and the minimum file schema
discovery needed to construct the result schema before it returns a
`QueryResult`. Dropping or cancelling that future aborts in-flight discovery;
after it returns, use `QueryResult::cancel()` or its cancellation handle.
